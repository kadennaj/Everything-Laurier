## Implemented and deployed

A successful request is counted, and concurrent counters are updated atomically. A denied/invalid transaction rolls back, so these are operation quotas, not a complete network denial-of-service defence. Profile upserts count once per completed row operation.
- Tutor creation retains the existing 5/hour and 10 active application limits, adds 10 new applications/account/day and 200 globally/day. Transcript insertion is reserved to an applicant-owned draft, cannot overwrite files, retains the 8 MiB JPEG bucket limit and short signed reads, and adds a conservative 1 GiB total bucket cap plus upload counters. Storage authorization serializes capacity checks. This caps accepted object sizes, not the bandwidth consumed by rejected uploads. Provider-level controls are still required.
- Both sync endpoints retain their server-only token verification, then reserve a durable budget before fetching providers. At most 6 attempts/job/UTC day, with a one-hour minimum interval within each day. Normal schedule remains 3/day. Failed attempts consume budget; budget outages fail closed. Apify retains its US$0.05 per-run limit, so configured job attempts permit at most US$0.30/day (US$9.30 over 31 days) in scraper run charges if the provider honours that run cap. This is NOT a cap on the overall Apify, Supabase, email or hosting account invoice. Responses and timeouts are bounded. Owner dashboard shows current job counts, application capacity and transcript size.
- Private consent records store account ID, current terms/privacy version, 16+ self-confirmation and time; no birth date. They gate protected user submissions on the server. Public browsing, retrieving own data, disabling discovery, withdrawing applications and deleting accounts remain available without accepting new account terms. Direct Auth requests can still create an Auth identity without a profile; production CAPTCHA/age handling below remains necessary.
- “Your data & choices” shows current account summaries, sharing settings, local choices, an explicit data-copy action and access/correction/deletion contact. Exports allowlist fields and exclude session tokens; report exports cap at 1,000, with full access via support. Transcript files and provider logs need a separate access request. Data previews clear on leaving the page. Private records remain scoped by server-verified identity, never a caller-supplied user ID. Existing account deletion revokes sessions and deletes storage before deleting the account; cascade deletion includes new counters/consents.
